# 小小探險隊 V6.4｜正式 Image Generation Pipeline

## 1. Identity source of truth

四個 learner 的唯一身份基準是網站既有角色：

- `public/assets/v5/characters/brother/wardrobe/base-body.png`
- `public/assets/v5/characters/younger/wardrobe/base-body.png`
- `public/assets/v5/characters/sister/wardrobe/base-body.png`
- `public/assets/v5/characters/younger-sister/wardrobe/base-body.png`

任何概念圖、Asset Pack、Lookbook、純文字生成人物都不能取代上述 Master Reference。

## 2. Formal output contract

每一件 wearable × 每一個 avatar 的 Hero Composite：

- 1024 × 1536
- transparent background / alpha
- Character center X = 512
- Ground baseline Y = 1488
- 相同鏡頭、站姿、臉型、眼睛、身體比例與角色辨識度
- 僅改變指定裝備／服裝
- lighting / material / occlusion 必須與人物整合，不得有拼貼感

正式輸出位置：

`public/assets/v6.4/hero-composites/{avatar}/{itemId}.webp`

World item：

`public/assets/v6.4/world/{slot}/{itemId}.webp`

概念／Lookbook：

`public/assets/v6.4/lookbook/`

Lookbook 不可當成 production Hero Composite。

## 3. Pilot batch

第一批先做四個角色 × `starter-sun-cap`（晴空小隊帽）。

目的：驗證同一件帽子在四個網站原角色上能保持身份、正確貼合頭型、光影一致且無拼貼感。

Pilot 只有在四角色全部 Visual AI Review 通過後，才可批次擴展到另外 47 件 wearable。

## 4. Visual review gate

每張正式圖至少評分：

1. Character Identity
2. Anatomy
3. Equipment Alignment
4. Lighting Consistency
5. Material Quality
6. Occlusion
7. Visual Appeal
8. Child Appeal
9. Rarity Readability
10. Overall Polish

每項 >= 8，Overall >= 8.5。

任何一項不合格：重新生成／修圖，不用 CSS top/left/scale 硬救。

## 5. Runtime policy

- Hero Composite 用於 Shop 大型 Preview、Before/After、Unlock Reward、收藏展示。
- Runtime Layer 繼續使用 fixed-canvas contract，支援多件裝備組合。
- Outfit 一律視為 Full Character Skin；不得把衣服 thumbnail 貼在人物身上。
- Backpack/Cape 採 split-depth layer，必要的前後景由資產本身解決。
- Equipment state 與 render visibility 分離，透過 `occludes` / `conflictsWith` / `zLayer` metadata 控制。

## 6. Release protection

在 192 wearable records、15 world records、24 large-display Visual Review 未全部 PASS 前：

- 不升 `6.4.0`
- 不部署 Production
- 不把 PENDING 改成假 PASS
