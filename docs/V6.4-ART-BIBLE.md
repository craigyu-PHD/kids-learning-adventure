# 小小探險隊 V6.4 Art Bible

狀態：V6.4 authoritative visual-production contract
Production baseline：V6.3.0 · Updated 2026-09-02
建立：2026-09-02

## 1. Product Visual Goal

小小探險隊不是一般學習管理網站。正式角色與寶物必須讓 5–10 歲兒童產生「想收藏、想升級、想繼續完成任務」的動機。

以下都不是美術完成標準：

- 圖片有出現。
- 沒有 404。
- Overlay 成功。
- DOM / Playwright 可見。

正式美術完成標準：角色穿戴後看起來像原本就以完整造型被製作完成，而不是透明圖片拼貼。

## 2. Character Style

原創、高品質、2.5D / 3D 兒童冒險動畫視覺：

- 精緻、明亮、溫暖。
- Premium toy-collectible feeling。
- 動畫電影級柔和 lighting / rim light / volumetric light。
- 清楚 silhouette。
- 材質有辨識度與細節，但不寫實恐怖。
- 適合 5–10 歲。
- 不模仿任何特定動畫、遊戲或既有 IP。
- 禁止 emoji / stock / generic clipart / CSS 幾何圖形當正式資產。

## 3. Production Characters

固定四位：

- `brother`
- `younger`
- `sister`
- `younger-sister`

換裝後必須保持：

- 同一張臉與人物辨識度。
- 同眼睛、臉型、膚色、髮際與表情語言。
- 同身體比例、頭身比例、手腳長度。
- 同鏡頭、同基準站姿、同人物個性。

不得因每件裝備重新生成而變成另一個小孩。

## 4. Character Master Reference Contract

每位角色建立一份正式 Master Reference：

- Canvas：1024 × 1536。
- Transparent background。
- Character Center X = 512。
- Ground baseline Y = 1488。
- 固定 camera perspective。
- 固定 head/body proportions。
- 固定 hand / foot position。
- 固定 key light direction、soft fill 與 rim-light language。

所有後續 Hero Composite / Runtime Layer 必須以該角色 Master Reference 作 identity reference，不得只靠文字重新生成角色。

## 5. Dual Asset Architecture

### A. Hero Composite

每一件正式 wearable × 每位 production avatar 都要有完整角色穿戴成品。

用途：

- Shop large Preview。
- Before / After。
- Unlock Reward。
- Equipment Detail。
- 收藏展示。

Hero Composite 的視覺品質是正式 Art Acceptance 主體。

### B. Runtime Layer

仍使用 1024 × 1536 transparent fixed-canvas layer，支援多件動態組合與跨頁 AvatarRenderer。

Runtime Layer 可以是 aligned / split layer，但視覺上不能有拼貼感。

## 6. Wearable Contact / Lighting Contract

每件裝備必須具備：

- 同 lighting direction。
- 同 outline language。
- 同材質品質。
- 正確 perspective。
- 正確人體接觸點。
- 正確 occlusion。
- 接觸 shadow / ambient shadow。
- 正確 overlap / depth。
- 透明邊緣不得有 white fringe / halo。

禁止用 CSS `top/left/translate/scale` 作第一修復手段。若穿戴錯位，優先重新生成或修圖資產。

## 7. Theme Families

### Sky

藍白、天空、清爽、柔和雲光、輕量材質。

### Rocket

航太結構、推進器、速度感、功能細節、乾淨機械材質。

### Ocean

水藍、珍珠光、半透明材質、水波與氣泡語言。

### Nebula

紫藍星雲、柔和發光、宇宙粒子、深色但仍溫暖。

### Legendary

金 / 白 / 深藍，稀有材質、星環與特殊 silhouette。不能只是把普通品改成金色。

## 8. Rarity Readability

- Common：簡潔、清楚、可愛。
- Rare：增加材質差異、輪廓細節、功能造型。
- Epic：更特殊 silhouette、裝飾與光效。
- Legendary：最高辨識度、特殊結構、稀有材質、適度 premium effect。

不得只靠藍 → 紫 → 金換色區分稀有度。

## 9. Outfit

所有 Outfit 一律是 Full Character Skin / Hero Composite。

服裝需真正改變：

- 上衣。
- 下身。
- 鞋子。
- 局部配件。
- 材質。
- 色彩語言。

人物臉與體型不得改變。

## 10. Hair / Hat / Headphones / Glasses

Hair：沿頭型自然生長；髮際與耳朵關係合理。
Hat：帽冠、帽緣與頭頂接觸；不浮空。
Headphones：耳罩覆蓋耳朵，頭帶貼合頭型，與頭髮有合理遮擋。
Glasses：鏡框、鼻橋、鏡腳與臉型/耳朵對應。

Hair + Hat、Hair + Headphones、Hat + Headphones 是 V6.4 必測組合。

## 11. Backpack / Cape

Backpack：本體位於身後，肩帶與肩膀接觸，必要前帶可跨到手臂/胸前。
Cape：大部分在人體後方，肩扣/領口在前方，布料方向與重力合理。

Runtime 維持 back/front split architecture，但正式資產必須由 Image Generation / image editing 製作，不以 CSS 三角形或舊 thumbnail 替代。

## 12. World Art

### Spaceship

三艘飛船是三個不同 production designs，不是同造型換色。具備 cockpit / engine / wing / volume / ground shadow / rarity identity。Preview 使用 Hangar Stage，飛船是視覺主角。

### Robot

Sky / Mecha / Legendary 必須是不同 silhouette 與 personality。Preview 使用 Companion Lab，Avatar + Robot 雙主體。

### Card

正式收藏卡包含 illustration / frame / rarity ornament / foil-holographic language / iconography。卡片商品只影響卡片，不暗中改全站 Dashboard Theme。

### Effect

正式素材由 Image Generation 產生 particle atlas / glow / sparkle / star dust / bubble / legendary energy motif。動畫 event-driven，不整頁持續亂閃。

## 13. Shop Hero Stage

商品 Grid 不是第一視覺。點擊商品後優先展示高品質 Hero Composite / World Hero Art：

- Character → Dressing Room。
- Ship → Hangar。
- Robot → Companion Lab。
- Card → Collection Viewer。
- Effect → Effect Stage。
- Room → Adventure Base。

Wearable Preview 要有「現在 / 試穿後」切換，並另有完整 Look Preview。

## 14. Fine-Grained Visual Slots

正式視覺 slot：

- skin
- hair
- headwear
- earwear
- face
- backpack
- cape
- hand
- effect

World：

- spaceship
- room
- robot
- card

Equipment state 與 visibility 分離；`occludes` 只暫時隱藏被遮裝備，不得自動 unequip。

## 15. Visual Acceptance Gate

每個 Asset Batch 必須產生真實 Browser Screenshot，交由具有圖片理解能力的視覺模型評分：

1. Character Identity
2. Anatomy
3. Equipment Alignment
4. Lighting Consistency
5. Material Quality
6. Occlusion
7. Visual Appeal
8. Child Appeal
9. Rarity Readability
10. Overall Polish

任何單項 < 8/10：FAIL，重新生成或修圖。
Overall < 8.5/10：不得進 Production Asset。

## 16. Image Generation Requirement

所有 V6.4 正式新美術必須由內建 Image Generation 產生或以該工具進行 image editing。

禁止正式替代方案：

- CSS 畫裝備。
- Emoji / icon / SVG 幾何圖形冒充裝備。
- catalog thumbnail 放大。
- hue-rotate / filter 冒充不同商品。
- gradient 改背景冒充重新設計。
- stock image。

若 Image Generation 不可用，V6.4 art-production 必須停止並記錄 blocker。

## 17. Asset QA

每個 production asset 檢查：

- resolution / aspect ratio。
- transparency / alpha edge。
- WebP decode。
- file size budget。
- duplicate hash。
- naming。
- avatar/item coverage。
- fixed canvas geometry。
- Hero Composite / Runtime Layer pairing。

Master source 可保存 PNG；runtime 優先 optimized WebP。

## 18. Performance Contract

首頁不得 preload 全部 48 × 4 Hero Composite。

進入 Shop 後只優先下載：

- active avatar。
- active category。
- visible items。
- active preview。

其餘 lazy load。

## 19. Hard FAIL Examples

以下任一狀況視為美術 FAIL：

- 肉眼明顯是圖片貼圖片。
- 裝備浮空或穿模。
- 不同光向 / 色溫 / outline。
- 角色臉或身形因裝備而變人。
- 高稀有度只換色。
- Hero Composite 沒有真正完整角色。
- 4K 舞台很大、角色/商品仍縮成小圖。
- Shop 只證明 image visible 而沒有 visual-model approval。
